# High-end website direction and reuse

Design for the user's brand, purpose, audience and intended action. High-end can be
quiet and static, richly editorial, product-focused, playful or cinematic. Scroll
effects are one technique, not a requirement or a quality score. Prioritize coherent
art direction, typography, spacing, useful content, responsive composition and finish.
Do not impose a default section count, palette, animation quota or signature move.

## Platform choice for every reference pack

Reference packs supply design direction, prompts and assets; their source platform
is not the default build platform. Follow the user's chosen stack, or retain the
existing project/host stack. For a new project without a chosen stack, use a suitable
responsive frontend for the brief and hosting environment. WordPress and WooCommerce
are optional: use them only when the user requests or agrees to them, or is already
working on an existing WordPress site. A bundled WP theme, source installation guide
or source prompt mentioning WP does not count as that choice.

This applies to Layer, Frostwood and every future pack, including verbatim and
hybrid reuse. Preserve requested design, assets and interactions while adapting
platform-specific instructions to the selected stack; keep the original prompt
unchanged and disclose the technical adaptation. Reproducing a visual design does
not require reproducing its CMS. Treat theme code as an optional implementation
reference, not an installer to run by default. Add a CMS or commerce backend only
when the project needs it; product selection alone does not imply WooCommerce.

## Three supported ways to use the library

- **Verbatim:** reuse a supplied prompt exactly; reproduce template structure,
  styling and interactions faithfully; use supplied assets as-is. Change only what
  the user asks to change or what the target platform requires. Preserve a source
  copy, record necessary technical adaptations, and do not silently rewrite prompts
  to satisfy a vendor skill's uniqueness preferences.
- **Guided adaptation:** use prompts, templates and assets as references or starting
  points. Follow the user's other ideas/references, rework composition and copy,
  combine suitable patterns, and tailor media prompts to the new project.
- **Hybrid:** preserve named elements exactly and adapt the rest. Record which are
  locked (for example a hero prompt, asset, layout or typography) and which are flexible.

Infer the mode from a clear request. If materially ambiguous, ask a concise question
about what must stay exact while continuing independent preparation. Both exact reuse
and adaptation are first-class workflows; neither is a fallback. Use the relevant
source material directly instead of inventing substitutes when it has been supplied.
Do not claim an asset was used verbatim after cropping, recolouring or regenerating it.
Model output remains variable even when the prompt is reproduced verbatim.

## Uploads and future library additions

Inspect uploaded templates/references before describing them. Preserve original
source text/files and keep an adapted working copy separately. Register provenance,
intended use, editable/locked elements and dependencies in the catalog/TEMPLATE.md.
References can guide a project without being imported into a public distributable.
Keep existing credits/licenses with copied material. Technical validation cannot
decide asset ownership or turn a reference link into rights to its source media.

The user can keep adding website templates, prompts, screenshots, assets and design
references. Do not assume a promised upload has already arrived or invent its design.
Once supplied, use the requested exact/adapted mode. New media selected from these
sources still needs approval in this chat before web publication; previously approved,
unchanged assets retain their approval. See media.md and maintaining.md.

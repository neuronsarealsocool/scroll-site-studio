# Alpine editorial retreat

Build a polished editorial website for an alpine retreat. Establish the visitor's
next action before laying out the page. Compose a large photographic opening,
quiet navigation, an expressive headline, readable supporting copy and one clear
primary action. Use the supplied hero/exterior/interior/footer photographs for
their intended roles; composition references guide spacing rather than becoming
flattened screenshots of the interface.

Define typography, warm/cool neutrals, spacing, maximum content width, controls and
image treatment as shared tokens. Balance generous whitespace with strong image
coverage. Follow the retreat's real offer through introduction, accommodation or
spaces, editorial highlights, image gallery and closing invitation. Choose the
section order and copy that answer the actual brief; do not invent awards, reviews,
prices, availability or booking confirmation.

Make navigation destinations real. A gallery needs reachable controls and useful
captions; a booking action needs its actual destination or a clearly labelled demo
state. Preserve image aspect ratios, tune focal crops and reserve layout space to
avoid shifts. Load the opening image first and defer lower images. Use restrained
entrances only when useful. Recompose narrow layouts with legible type, deliberate
image crops and touch targets. Test the complete page and primary action.

The manifest contains 19 distinct files, including two composition references.
Theme code is not required for this frontend direction and is not bundled here.

## Project rules

Use this working prompt as written, adapt it, or lock selected elements and combine
the rest with the user's other ideas. Establish the real brand, audience, purpose,
primary action and required functionality. Keep the existing or chosen stack; for
a new project choose a suitable responsive frontend. WordPress and WooCommerce
are optional. Motion is optional unless required by this selected experience.

Default to Replicate for new media, using the bundled media workflow. Confirm the
model inputs and authorized budget before paid jobs. Show newly selected/generated
media in chat and obtain approval before putting it on any public site, preview,
CDN or repository. Reuse explicit approval for unchanged assets. The library host
is asset storage, not automatic approval for every future project's use.

Use real HTML text and semantic controls. Keep content useful before media loads.
Implement keyboard access, visible focus, touch controls, reduced motion, loading
and failure recovery. Test desktop, mobile, short screens and resize. Verify real
actions and label demonstration data. Do not claim a connected backend or measured
performance without testing it. Preserve applicable license notices; hosting a
copy does not grant new rights to brands, fonts or media.

# Coffee product carousel

Build a premium coffee product showcase with one prominent selected drink on a
warm cream studio background and a curved ingredient selector. Keep the selected
product name, description, options and primary action visually coherent. Use the
hero composition reference to establish the relationship between cup, tray,
ingredients and typography. Keep every control as HTML rather than baking it into
the image.

The five product families are caramel, mocha, strawberry, pistachio and brown sugar.
Pair each cup with its matching ingredient using the media role labels. Use the
background and three editorial photographs to extend the visual system below the
hero. Product selection must work with keyboard, pointer and touch. Keep pending
selection and committed name/options/price aligned during transitions. Handle rapid
selection without stale images or out-of-order state commits. Include a restrained
reduced-motion change and a useful fallback when an image fails.

If generating a replacement set, make one approved master cup first. Lock camera,
cup/tray bounds, scale, horizon, light direction, transparency and text-safe space.
Generate matched variants through Replicate, then inspect contact sheets, overlays,
transparent edges and crop consistency. Similar styling alone does not establish
alignment. New generated variants require the normal budget and media approvals.

Compose phones separately so product, label, selector and purchase action remain
legible and reachable. Keep enough vertical room for short screens. Below the
product experience use editorial brand/ingredient/store sections that fit the
brief. No product CSV, real prices or checkout data are supplied. Connect actual
commerce only within scope and test every variant, cart/error state and checkout.
A visual selector by itself is a demo, not a functioning store.

The manifest supplies five cups, five ingredients, one background, three editorial
photographs and one hero composition reference. No particular commerce platform
is required.

## Project rules

Use this working prompt as written, adapt it, or lock selected elements and combine
the rest with the user's other ideas. Establish the real brand, audience, purpose,
primary action and required functionality. Keep the existing or chosen stack; for
a new project choose a suitable responsive frontend. WordPress and WooCommerce
are optional. Motion is optional unless required by this selected experience.

Default to Replicate for new media, using the bundled media workflow. Confirm the
model inputs and authorized budget before paid jobs. Show newly selected/generated
media in chat and obtain approval before putting it on any public site, preview,
CDN or repository. Reuse explicit approval for unchanged assets. The library host
is asset storage, not automatic approval for every future project's use.

Use real HTML text and semantic controls. Keep content useful before media loads.
Implement keyboard access, visible focus, touch controls, reduced motion, loading
and failure recovery. Test desktop, mobile, short screens and resize. Verify real
actions and label demonstration data. Do not claim a connected backend or measured
performance without testing it. Preserve applicable license notices; hosting a
copy does not grant new rights to brands, fonts or media.

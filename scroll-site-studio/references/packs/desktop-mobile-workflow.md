# The Visual Story Method

Build a high-end responsive website around the actual business and visitor action.
Use the following planning and implementation method within the chosen project.

## Two-stage working method

1. **Desktop Build first.** Establish the offer, audience, identity and primary
   action from supplied information. Ask only for materially missing facts. Keep
   official brand assets; identify fictional placeholders and avoid invented trust
   claims. Use guided checkpoints when requested or sensible autonomous decisions
   when authorized. Do not manufacture payment, form or booking destinations.
2. **Build a style tile.** Use actual site tokens for palette, typography, logo,
   buttons, links, representative content and imagery direction. It is a compact
   design sample, not a completed website screenshot or mandatory brandbook.
3. **Present the Visual Story.** Keep exactly three columns: `Scene`, `Visual story`,
   `Website copy`. Pair meaningful action and copy; include transition-only beats
   when needed. Add a pacing plan below the table, covering framing, entry/exit,
   active travel in viewport heights and deliberate holds. Three scenes and short
   clip examples are starting points, not fixed requirements for every site.
4. **Keep continuity in the footage.** Decide on one continuous sequence or matched
   connected clips. Produce dependent clips in order and inspect the chosen outgoing
   frame before passing that exact raster reference to the next compatible model.
   Compare scale, position, identity, lighting and motion at each join. A crossfade
   or longer scroll distance cannot repair footage that never isolates its subject.
5. **Map pacing independently.** Use separate frame ranges per story beat, with
   holds mapping to one frame. Allocate readable HTML copy intervals and normal
   page flow outside the pinned story. More extracted frames do not create more
   scroll travel; a few stretched frames do not create smooth continuous action.
6. **Prepare and integrate.** Retain original clips, prompts/settings and prediction
   IDs. Use FFmpeg/ffprobe when needed; the 18fps/WebP/size examples are
   adjustable. Verify actual frame count, dimensions, numbering, poster and endpoints.
   Keep semantic text/controls separate from generated pixels and content editable.
7. **Mobile Refinement second, in the same project.** Recompose phone navigation,
   copy, framing and pacing. For the selected sequence experience plan dedicated portrait media, approximately 9:16, with coherent product and
   brand identity. Reuse suitable existing approved portrait media first; do not
   stretch desktop video or duplicate the entire website. Check desktop again.

## Delivery and acceptance

Keep mobile navigation above the complete page, outside pinned ancestors. Maintain
safe areas, accessible menus, focus handling and anchor offsets. Keep the opening
clear, the final product readable, and a way to skip the story readily available.
Match requested camera movement in actual media; an in-plane rotation is not a
substitute for a missing camera orbit. Avoid exposed edges during transforms.

Choose the active media variant before sequence requests; do not preload both
versions and hide one with CSS. Use an immediate poster, progressive nearby-frame
loading, bounded concurrency and decoded memory, stale-response protection and
resource cleanup. Reduced motion uses a composed still and normal flow without
fetching the animation sequence. Preserve a useful fallback if media fails.

Check actual opening, joins, final reveal, forward/reverse/fast scrolling, navigation,
menu reachability, forms/actions, responsive changes and reduced motion. Record
measured asset sizes separately from loading-speed measurements. Compilation alone
does not verify visual quality, animation pacing or physical-phone behaviour.
Publish only within the authorized audience and after media approval.

## Project rules

Use this working prompt as written, adapt it, or lock selected elements and combine
the rest with the user's other ideas. Establish the real brand, audience, purpose,
primary action and required functionality. Keep the existing or chosen stack; for
a new project choose a suitable responsive frontend. WordPress and WooCommerce
are optional. Motion is optional unless required by this selected experience.

Default to Replicate for new media, using the bundled media workflow. Confirm the
model inputs and authorized budget before paid jobs. Show newly selected/generated
media in chat and obtain approval before putting it on any public site, preview,
CDN or repository. Reuse explicit approval for unchanged assets. The library host
is asset storage, not automatic approval for every future project's use.

Use real HTML text and semantic controls. Keep content useful before media loads.
Implement keyboard access, visible focus, touch controls, reduced motion, loading
and failure recovery. Test desktop, mobile, short screens and resize. Verify real
actions and label demonstration data. Do not claim a connected backend or measured
performance without testing it. Preserve applicable license notices; hosting a
copy does not grant new rights to brands, fonts or media.

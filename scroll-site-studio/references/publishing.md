# Optional publishing adapters

Choose the requested host. Preserve an existing project's identity and audience.
Honour local-only/save-only work and the mandatory in-chat media approval gate.
Before publishing any site, preview, media CDN, public source repository or release,
check the approval record for every new media asset. Keep pending versions local
or in an authorized private backup, and use placeholders while review is pending.
Private backup authorization does not approve public display. Do not host review media to satisfy
a delivery/link helper. Previously approved unchanged live assets retain approval.
Skill installation does not
authorize publication. Use the host's current supported workflow and credentials.

## Sites connector

Where available, read the installed Sites skill. This package does not redistribute
that plugin or make its connector available in Claude. Reuse the actual opaque
project ID from .openai/hosting.json. Open source with fresh credentials before
editing, build/check exact source, then use the helper's commit/push/archive result
to save and deploy the matching version using the audience-appropriate operation.
Keep IDs across retries and poll nonterminal status. Credentials use supported
stdin/in-memory interfaces, never shell arguments. Success needs a returned live URL.

Windows lessons: spaces/parentheses can expose brittle npm shims; supported direct
Node entrypoints are a remedy after diagnosing that failure. Git-Bash tar can treat
D: as a remote; TAR_OPTIONS=--force-local helped our specific helper configuration.
Do not apply these workarounds universally or copy another project's hosting ID,
database binding, enquiries or form secret.

## Static hosts and delivery

Starters have index.html plus assets, usable with ordinary static hosts. If here.now
is chosen and available, read its installed skill and https://here.now/docs at use
time. Otherwise use the recipient's chosen supported host. Verify actual URL/media
responses. A local build is not a deployment.

Return local files and supported share/download links when available. Do not expose
credentials/state in a delivery root, invent cloud links after failures or imply
localhost works on a different phone. Reuse a designated delivery site rather than
consuming a new permanent address for each artifact.
